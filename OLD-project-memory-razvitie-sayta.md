## ⚠️ Критическое правило — никогда не нарушать

**Не вставлять CSS в поле «Пользовательские CSS» темы UniTheme2.** Ранее это привело к белому экрану и откату из бэкапа. Все стилевые изменения — только через цветовой редактор темы.

Единственное задокументированное исключение: resize лого (`.ty-logo-container img`, 63px) через Custom CSS — сделано осознанно с инструкцией по откату («Сбросить CSS»).

<sub>В снимке селектор слипся в `.ty-logo-containerimage` — при извлечении текста из HTML пропал пробел. Восстановлен как `.ty-logo-container img`; перед применением сверить с фактическим CSS.</sub>

1. Тест `zamerny-list-v2.html` на живом замере (гардеробная) → собрать, что мешает в полях

## Ключевые выводы и принципы

- **Ворота работают только если не на владельце.** Процессы, которые Михаил заполняет сам поверх остального, умирают «для галочки». Лист замера → нанимаемый замерщик; лист перед ЧПУ → Сергей (на месте, независимый глаз, последний перед резом дорогого материала).
- **Инструмент обязан быть быстрее текущего способа**, иначе не приживётся.
- Приложение для разметки фото строить не нужно — есть зрелые решения (Leica DISTO Plan уже есть, SizeSnap, Photo Measures, ImageMeter). Уникальная ценность — **система ворот**, а не ещё одна линейка на фото.
- Правило разметки размеров на фото: цифра + метка типа. **В** = высота от пола, **У** = от угла, **Г** = глубина + назначение (Вода/Газ/Вент/Роз). Цвет — жёлтый/контурный.
- CRM и Битрикс — после обкатки ворот, не параллельно. Данные уже структурированы (JSON) → переезд будет лёгким.
- **Netlify недоступен без VPN в России** — все страницы хостятся на Timeweb.
- Физическая директория в Timeweb имеет приоритет над rewrite-правилами CS-Cart — `/b2b/`, `/links/`, `/materialy/` работают без конфликтов.
- Продажа системы сторонним мебельщикам — только после доказанного результата у себя.
- **Рабочий процесс файлов:** всегда загружать файл, который Claude производит в КОНЦЕ сессии, а не более раннюю версию — иначе предыдущие правки «откатываются».

## Подход и паттерны

- Работа ведётся итеративными сессиями; каждая сессия начинается с восстановления контекста через этот проект
- Михаил работает преимущественно с телефона → интерфейсы должны быть удобны на мобильном
- Приоритет: мелкие обратимые шаги → проверка через `?cc` + инкогнито → только потом следующий шаг
- Перед любыми правками — бэкап
- Стратегия «один переход за раз»: не строить всё сразу, обкатывать на реальных заказах
- Идеи (приложение, продажа) фиксируются, но откладываются до доказательства пользы на своём производстве
