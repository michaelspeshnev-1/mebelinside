## Правила

1. **Одна организация — один `@id`: `https://mebelinside.ru/#org`.** Так в `O-KOMPANII-otzyvy-teksty.md`.
   В `PROEKTY-keysy-teksty.md` (раздел 7) стоит `#organization` — при заливке кейсов заменить на `#org`.
   [?] Какой `@id` у `FurnitureStore` в JSON-LD **главной** (он уже есть, `SEO-GEO-UX-etap0-…` п. 34): Ctrl+U на главной →
   найти `"@id"`. Если там другой (или его нет) — либо добавить на главную `"@id": "https://mebelinside.ru/#org"`,
   либо во всех шаблонах заменить на тот, что на главной. Главное — один и тот же везде.
2. **Без `aggregateRating`, `review`, цен** (решение по отзывам и ценам; рейтинги живут на Яндекс Картах/2ГИС).
3. **FAQPage — один на страницу** и только если вопросы видны на странице текстом. На категориях кухонь FAQPage уже
   выводится (аудит 06.10) — [?] Ctrl+U → искать `FAQPage`: если есть, второй не добавлять, а заменить вопросы в существующем.
4. **BreadcrumbList не дублировать:** в карточках товаров и, вероятно, в категориях тема уже выводит крошки
   (`Product`+`BreadcrumbList`, аудит 06.10). [?] Ctrl+U → искать `BreadcrumbList`; если тема выводит крошки и на страницах
   CS-Cart — наш шаблон не нужен.
5. **Куда вставлять:** в конец описания страницы/категории, в редакторе — режим «Исходный код» (визуальный режим режет
   `<script>`). Если описание всё равно вырезает `<script>` — HTML-блок в макете этой страницы (Дизайн → Макеты) [?].
6. **Проверка:** Ctrl+U → `application/ld+json` в исходнике; валидатор Яндекса webmaster.yandex.ru/tools/microtest/ и
   validator.schema.org — 0 ошибок. Предупреждения про необязательные поля допустимы.
7. JSON строгий: без комментариев и висячих запятых. Комментарии-подсказки стоят **вне** `<script>`.
