**Контекст:** уже существует Telegram-бот, который публикует посты из канала `t.me/mebel_inside` на Дзен (`dzen.ru/mebelinside`). Задача — расширить его, чтобы те же посты автоматически становились записями блога на сайте (CS-Cart). Цель: сайт постоянно обновляется свежим индексируемым контентом без отдельной ручной работы.

## 1. Общая схема

```
Пост в TG-канале ──► существующий бот ──► Дзен (как сейчас)
                          │
                          └────► НОВОЕ: REST API CS-Cart ──► запись в блоге сайта
```

Одна точка публикации — Telegram-канал. Всё остальное автоматом.

## 2. Платформа сайта

CS-Cart (russian edition), тема AB UniTheme2. Хостинг Timeweb.

Блог CS-Cart — это страницы (pages) с типом «Блог» (`page_type: "B"`), лежащие под корневой страницей блога (`parent_id` корня блога — уточнить через GET, см. §4).

Блог сейчас выводится на главной блоком «Обзоры / Новости» и в разделе блога.

## 3. Доступ к API CS-Cart

1. В админке: **Администрирование → Пользователи**, открыть (или создать) пользователя-администратора для интеграции.
2. Вкладка **«API-ключ»** (или чекбокс «Да, разрешить этому пользователю использовать API») → сгенерировать ключ.
3. Рекомендуется завести ОТДЕЛЬНОГО пользователя `api-blog@mebelinside.ru` с минимальными правами (только управление страницами), чтобы не давать боту полный админский ключ.
4. Аутентификация — HTTP Basic: `email:API_KEY`. Только HTTPS.

Проверка доступа:

```
GET https://mebelinside.ru/api/pages/?page_type=B
Authorization: Basic base64(email:api_key)
```

Ответ покажет существующие записи блога и **`parent_id` корня блога** — записать его в конфиг бота.

> ⚠️ Из уроков журнала: **API-ключ копировать ПОСЛЕ «Сохранить»**, иначе скопируется старое значение.

## 4. Создание записи блога

```
POST https://mebelinside.ru/api/pages/
Content-Type: application/json

{
  "page": "<Заголовок поста>",
  "description": "<HTML-текст поста>",
  "page_type": "B",
  "parent_id": <ID корня блога из §3>,
  "status": "A",
  "timestamp": <unix-время публикации>
}
```

Ответ содержит `page_id` — сохранить в связке `tg_message_id → page_id` (SQLite/JSON у бота), чтобы:

- не публиковать один пост дважды (дедупликация);
- при **редактировании** поста в TG обновлять запись: `PUT /api/pages/<page_id>` с новым `description`;
- при **удалении** поста в TG (опционально) скрывать запись: `PUT` со `"status": "D"`.

**Внимание:** точный набор полей может отличаться в зависимости от версии CS-Cart и аддона блога — перед разработкой сделать один GET существующей записи блога и скопировать структуру её полей.

> ⚠️ Из уроков журнала: **REST `pages` не ставит `main_pair`** (главное изображение) — учитывать.

## 5. Преобразование поста TG → запись блога

- **Заголовок** = первая строка поста (до перевода строки), максимум ~90 символов. Если первая строка длиннее — обрезать по последнему слову и добавить «…».
- **Текст** = остальной текст поста; преобразование разметки TG (жирный/курсив/ссылки) в HTML. Абзацы — через `<p>`.
- **Фото:** URL файла Telegram содержит токен бота — использовать его напрямую **НЕЛЬЗЯ**. Бот должен:
  1. скачать фото (наибольший размер);
  2. залить на хостинг сайта по FTP/SFTP (Timeweb) в папку, например `/images/blog/2026/07/`;
  3. вставить в `description` как `<img src="https://mebelinside.ru/images/blog/..." alt="<заголовок>" style="max-width:100%">`.

  Первое фото поста — в начало записи.
- **SEO:** если у страницы поддерживается поле `seo_name` — транслитерация заголовка (кириллица → латиница, пробелы → дефисы). Метаописание (если поле доступно) — первые ~150 символов текста без разметки.

## 6. Какие посты публиковать на сайт

Чтобы служебные/акционные посты канала не засоряли блог, выбрать один режим (согласовать с Михаилом):

- **Вариант A (рекомендуемый):** публиковать посты, помеченные хэштегом `#сайт` (opt-in). Хэштег вырезать из текста перед публикацией.
- **Вариант B:** публиковать всё, КРОМЕ помеченных `#несайт` (opt-out).

Минимальная длина поста для публикации: 200 символов (короткие «сторис»-посты пропускать).

## 7. Надёжность

- Очередь с повтором: если API сайта недоступен — повторить через 5/15/60 минут (до 5 попыток), лог ошибок.
- Лог всех публикаций: `message_id`, `page_id`, время, статус.
- Никаких токенов/ключей в коде — только в конфиге/переменных окружения.

## 8. Приёмка (что проверяем)

1. Пост с `#сайт` (текст + 1 фото) появился в блоге сайта в течение 5 минут: заголовок = первая строка, фото отображается с домена mebelinside.ru, вёрстка не разъехалась.
2. Тот же пост появился на Дзене (существующая логика не сломана).
3. Пост без хэштега (при варианте A) НЕ появился на сайте.
4. Редактирование поста в TG обновило запись на сайте.
5. Повторная отправка того же поста не создала дубль.
6. Запись видна в блоке «Обзоры / Новости» на главной и открывается по своему URL.

## 9. Справочно: что НЕ входит в задачу

- Публикация в Яндекс.Карты — у Карт нет публичного API для постов, этот канал остаётся ручным.
- Виджет TG-ленты на сайте — не требуется (iframe не индексируется, SEO-задачу не решает).
